REPRODUCE / COMPARE / REPORT
Reproduce the BRAINLLM build benchmark on my machine. Read bench/build/expanded.md and inspect bench/build/expanded.mjs in https://github.com/chrisifm/BRAINLLM before running anything. Verify the prerequisites and use a dedicated scratch directory; preserve my work and do not change the benchmark fixtures. Use the pinned reference dependencies and the same workload, run count and warmup for every tool. Record the compiler commit and binary hash, machine details, versions, cold and warm timings, variance and payload sizes. Report failures and rendering differences honestly. Compare with the recorded results without claiming a universal speedup. Clean up only the processes and scratch resources you own. Do not publish results or install missing system tools without my approval.

The recorded fixture is your starting point. Fresh measurements belong to their exact machine, versions and workload.

THE COMPILER CAN BE PART OF THE WORK

Build with it.
Let your LLM
make it better.

Your agent found a compiler bug while building your app? Give it a path to propose the fix.

A better app can leave behind a better toolchain.

The agent can reproduce a framework defect, work in an isolated proposal and add a regression test. For a performance idea, it measures the same workload before and after.

Passing the gates produces a validated compiler candidate. Local activation is reversible. With automatic contribution configured, the exact validated commit goes to a review branch.

The agent proposes. The maintainer reviews. No automatic merge or package publication.
